## 2. 구현 (`pipeline/p6_scoring.py`, 220줄)

- **1·2단계 분리를 함수 시그니처로 보장 (검증 3번)**: `stage1_eup_ranking(usage: dict)` —
  좌표 인자 없음, usage_monthly 집계만 / `stage2_candidates(eups_by_rank: list[str], select_n)` —
  usage 인자 없음, 소진공 상가 캐시·merchants.json 좌표만. 두 단계는 **읍 이름 목록으로만 연결**되며
  한 수식에 두 단위가 섞이는 지점이 없다.
- 산식은 06 P6 주석 + common.py 상수 그대로 (EUP_WEIGHTS 0.5/0.5, CAND_WEIGHTS 각 1/3, ANCHOR,
  RADIUS_M 500). min==max → 전원 0.5 가드(15 §5)를 소비증감·근접도·포화도 3곳 공통 적용(`minmax01`).
  분기 정의는 P5 `growth.qoq_pp`와 동일(최근 2025-10~12 vs 직전 2025-07~09), base_month에서 유도.
- 표시 분류는 `store_display_category()` 단일 경로(None·"기타" 제외 → 후보 5분류).
- **구현 결정 2건**: ① "상위 1~2개 읍" → 상한 2 채택(`SELECT_EUPS = 2`) — B4 AI 비교(05 §2 카드
  예시)가 두 읍의 후보를 전제. ② 반경 분모·가맹점 카운트는 6개 지역 캐시 합산에서 계산 — 읍 경계에
  걸친 반경 500m가 이웃 지역 상가를 놓치지 않게(위도 창 bisect 1차 컷 + haversine 확정, 전체 1.1s).
- 예외 경로: 선정 읍 후보 0개 → 차순위 읍 자동 재시도 + stdout 로그. 방어 가드: 반경 내 상가 0
  후보 제외(로그), ANCHOR 동일 좌표·전분기 0건은 명시적 SystemExit.

## 6. 우려·후속

- **최대 우려 = §3의 서사 불일치.** eup_scores·candidates를 이대로 쓰면 B4 카드·F4 지도가 영월군
  중심이 된다. 11 §1 데모는 seed_demo.py가 카드 상태를 보장하므로 데모 자체는 성립하나, "실데이터
  근거" 서사가 약해진다. 산식 재정의 여부는 컨트롤러 결정 필요.
- 상위 후보가 전부 gap 1.0·포화도 0.0이라 실질 변별은 근접도뿐 — P8 민감도 분석(T6)에서 Top3
  안정도가 높게 나올 것으로 예상되나, "외곽 고립 입지 우대" 특성은 발표 질문 대비 필요.
- 후보 상가가 이미 하이원 가맹점일 가능성은 미배제(브리프에 없는 요건이라 미구현 — 상호명 매칭으로
  추가 가능).
- `SELECT_EUPS = 2`·전 지역 캐시 합산 반경 카운트는 구현 결정(§2) — 리뷰에서 뒤집히면 상수 1개/
