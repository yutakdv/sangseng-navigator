# 10. 작업 순서 — Phase 0~6 (일자 구분 없음, 의존성 순서대로)

> 날짜로 나누지 않는다. **각 Phase의 완료 조건(Gate)을 통과하면 다음 Phase로** 넘어가며,
> 토큰이 허용하는 한 연속으로 진행한다. FE 트랙은 Phase 1 이후 항상 병렬 가능
> ([F] 태스크는 mock 기반이라 BE 진행과 무관). 밀리면 `01-overview.md` 컷 리스트 순서로 자른다.
> 표기: [유] = 유탁, [F] = FE 팀원.

## 의존성 지도

```
Phase 0 (준비·블로커 해소)
   └─▶ Phase 1 (스캐폴딩 + 배포 왕복 확인)
          ├─▶ Phase 2 (데이터 파이프라인)  ──▶ Phase 3 (백엔드 코어) ─▶ Phase 4 (AI) ─▶ Phase 5 (연동·부가)
          └─▶ [F] F2~F8 화면 작업 (mock 기반, Phase 2~5와 병렬)          ─▶ Phase 6 (실배포·리허설·발표)
```

## 리스크 → 트리거 → 대응

| 리스크 | 트리거 | 대응 |
|---|---|---|
| API 승인 지연 | Phase 2 시작 시점까지 미승인 | 목업 CSV로 파이프라인 완성, 승인 즉시 원본 교체 (구조 동일) |
| 지오코딩 실패율 높음 | 성공률 < 80% | 실패분 제외 + 실패율 발표 명시 (기획안 대응 그대로) |
| LLM 출력 불안정 | 스키마 위반 반복 | JSON 스키마 강제 출력 확인 → 그래도 실패 시 규칙 기반 fallback 카드 |
| 2단계 후보 0개 | 선정 읍 상가 데이터 부족 | 차순위 읍 자동 재시도 (P6 예외처리) |
| 지도 렌더 이슈 재발 | Safari에서 지도 깨짐 | 02 문서 지도 결정 참조 — MapLibre 옵션 조정, 최종 폴백은 거리 표+정적 캡처로 대체 |
| 배포 이슈로 시간 소모 | Phase 6에서 2시간 초과 | 데모를 localhost로 전환, 배포는 리허설 후 재시도 (Phase 1 왕복 확인이 이걸 예방) |
| FE 일정 지연 | Phase 4 종료까지 F3 미완 | 유탁이 F5(대시보드) 인수, FE는 허브·상세에 집중 |
