# 11. 데모 스크립트·발표 구조·예상 질문 대응 (Phase 6)

> 기획안(MVP 개정판 §10·§11)을 실행 가능한 클릭 단위 스크립트로 옮긴 문서.
> 리허설 10회의 기준이며, 발표 담당이 이 문서만 보고 데모를 재현할 수 있어야 한다.

## 0. 두 종류의 관객 — 발표 데모 vs 무안내 심사

이 스크립트는 발표자가 조작하는 **발표 데모** 기준이다. 그런데 심사는 별도로 **심사위원이 안내 없이
배포 URL에 직접 접속**해서도 이뤄진다 (12 문서). 무안내 접속에서도 서사가 전달되도록:

- 첫 화면(허브)의 히어로·AI 브리핑만 읽어도 "무엇을 하는 서비스인지" 30초 내 파악 가능해야 한다
- README 상단에 "30초 둘러보기" 경로(§1의 1→8 요약)를 적어 심사위원의 셀프 데모를 유도한다
- 심사위원이 승인/반려를 눌러 상태가 바뀔 수 있음 → 시드 리셋 운영 (09 문서 §5.5)

## 1. 데모 클릭 스크립트 (목표 30초 × 반복 리허설, 실제 발표에선 9분에 걸쳐 해설과 함께)

> **데모 전 필수 절차**: `docker compose run --rm seed`(= `seed_demo.py --reset`)를 **반드시 먼저**
> 실행한다. 이력 카드·추진 기록이 이 명령으로만 들어가고, `pytest`를 돌리면 테이블이 코어 3장으로
> 되돌아가 아래 수치가 나오지 않는다. 리허설·심사 직전에 한 번씩 돌릴 것.

사전 상태(`seed_demo.py --reset`이 보장 — 영월군 서사, 실측 candidates.json 기준.
2026-08-08 이력 카드 보강 — 카드 상호·단계는 `backend/seed_demo.py`가 정본): **카드 5장**
① AC-001 "영월군 음식점 업종 가맹점 확충" EXPANSION 카드가 `approved+후보 접촉·검토 시작`
   (2일 전 생성·1.5일 전 승인, 적격성 5항목 미확인, **추진 기록 0건** — 데모 6단계의 대상이자
   "경과 기록이 없는 승인 카드" 목록의 표본), — 정량 1위 유지(adjusted=false)
② AC-002 "영월군 소매점 업종 가맹점 확충" 카드가 `pending` — 정량 1위(음식점)가 진행 중인 업무라
   서버가 중복 제안에서 제외하고 **선택 가능한 후보 1위(원 순위 2위, Score 0.49)를 선택한 조정 사례**.
   리허설·심사 리셋 때 서사가 항상 같게 나오도록 **LLM 호출 없이 고정한 JSON**이다(15 §5 T11),
③ INC-001 INCENTIVE 카드 `pending`,
④ **AC-003 "삼척시 편의점" `완료`** (이력 카드, 기록 5건) — 이번 분기 선정 지역 2곳 중 삼척시 몫으로
   분기 초에 끝낸 업무다. 이 카드 덕분에 **방문객 위젯의 `이번 분기 확충 업종` 배지가 데모 동선을
   밟기 전에도 보이고**, 추진 경과 리포트의 완료율·단계별 소요·목표일이 실제 값으로 채워진다,
⑤ **AC-004 "삼척시 카페" `추진중`** (이력 카드, 기록 4건, 마지막 기록 22일 전) — 정체 점검 표본.

리포트 실측값(리셋 직후): 기록 9건 · 기록 카드 2 · 미기록 1 · 완료율 50% · 목표일 내 완료율 100% ·
정체 1건(AC-004, 22일) · 단계 전이 4쌍 · 관측 성과 4종. **지역 사용액(원)만 비어 있는데 이는 의도**다 —
원천 데이터에 금액 필드가 없어 시드가 먼저 지어내지 않는다(13 §2-13).

> **고정 시드 ↔ 실시간 생성 구분 (대본 전체에 일관 적용).** ②는 *재현성을 위해 고정한 예시*이고,
> AI가 실제로 하는 일은 §1의 **2-b 단계("실시간 확충 제안 생성" 버튼)**에서 실시간으로 보여준다.
> 실시간 생성은 **호출마다 결과가 달라질 수 있다** — 그래서 카드에 원래 정량 순위(`original_ranking`)를
> 항상 병기해 담당자가 직접 판단하게 한다. 고정 카드를 "AI가 방금 해낸 것"처럼 말하지 않는다.

"지금은 fallback 문구가 나왔습니다"라고 그대로 말하고 넘어간다(숨기지 않는다).

3~5단계의 클릭 대상은 **항상 ②의 고정 카드(영월군 소매점 AC-002)**다 — 2-b에서 생성된 카드는
후보·사유가 호출마다 달라져(현 시드 기준 가용 1위는 원 순위 3위 숙박업) 3~4단계 해설과 어긋날 수 있다.
2-b 카드는 허브 목록에 쌓인 모습만 보여준다. 심사위원이 그 카드를 열어보면 원 정량 순위가
병기된 화면이 그대로 나오므로 문제되지 않는다.

## 2. 발표 구조 (15분 — 기획안 §10 그대로)

1. **오프닝 (1분):** "우리는 예쁜 대시보드가 아니라, 담당자가 실행할 근거를 만들었습니다"
2. **문제 정의 (2분):** 소비 집중도 지표 부재 + "리조트는 붐비는데 지역 전환율은 낮다"
3. **라이브 데모 (9분):** §1 스크립트 (해설 포함 버전)
4. **데이터·AI 설명 (2분):** 강원랜드 API + 소진공 + 국세청(역할 한정) + LLM 역할(제안자, 결정자 아님) + 가중치 민감도 결과(`top3_stable_ratio`)
5. **클로징 (1분):** 로드맵(대조군 비교, 매출 기반 정밀화, 페이백 자동 지급 연동) + 한 문장

발표 자료에 반드시 포함할 캡처/슬라이드:
- [ ] "Score 2위 → AI 1위" 조정 화면 캡처 — 슬라이드에 **"재현성을 위해 고정한 예시"**라고 함께 적고,
      실시간 생성 화면(§1-2-b) 캡처를 나란히 둔다 (고정/실시간 구분을 슬라이드에서도 유지)
- [ ] AI 입력 스키마 7종 표 (07 문서 B4 표 — ⑦ 요일 패턴 포함)
- [ ] 발표 인용용 프롬프트 **현행 전문** (07 문서 부록 A-1 — 구판 아닌 현행본을 실을 것)
- [ ] 민감도 분석 결과 1장 (combos·top3 유지율)
- [ ] 데이터 실사 결과 표 (기획안 부록 — 16개 검토, 6개 의도적 제외)
- [ ] 실제 CSV 컬럼 캡처 ("실제로 열어봤습니까?" 대비)
- [ ] 운영 비용 슬라이드 (AWS $0대 + Vercel $0 — Billing 스크린샷)

## 3. 예상 질문 → 답변 (기획안 §11 요약 + 시스템 구현 기준 보강)

| 질문 | 답변 요지 |
|---|---|
| 500m 수요를 어떻게 계산했나 | 500m는 수요가 아니라 업종공백도·포화도(좌표 데이터) 계산에만 사용. 수요는 읍 단위 1단계에서 별도 처리 — 애초에 섞이지 않는 단계 분리 설계 |
| 실제 CSV를 열어봤나 | 예 — 실컬럼 확인 캡처 + 레포의 `data/raw/` 원본과 COLMAP 코드 제시 |
| AI는 어떤 데이터로 판단하나 | 서버가 공백도·거리·포화도와 현재 추진 상태로 대상을 결정하고, AI에는 그 정본과 확정 타깃을 주어 비교 설명·비정량 리스크만 생성하게 한다 |
| AI가 틀리면 누가 책임지나 | AI는 대상을 바꿀 수 없고 설명만 보조한다. 수치·순위는 서버가 재구성하며 담당자 승인으로만 확정된다 |
| 결국 설명만 하는 것 아닌가 | 맞다. 수치 계산·대상 선택에 생성형 AI를 쓰지 않는 것이 재현성과 감사 가능성에 맞다. AI의 역할은 대안 비교와 검토 리스크의 읽기 쉬운 정리다 |
| 정량 1위를 AI가 조정한 사례 | 운영 중인 상위 후보는 서버 규칙이 중복 제안에서 제외한다. 생성형 AI가 임의로 순위를 조정하는 경로는 제거했다 |
| 데모의 조정 사례 카드는 실제 AI가 만든 건가 | 아니다 — **재현성을 위해 고정한 예시**다(LLM 호출 없는 고정 JSON, 15 §5 T11). 리허설·심사 리셋 때 같은 화면이 나와야 해서 그렇게 정했다. 실시간 생성은 별도 버튼으로 시연하며, **생성 결과는 호출마다 달라질 수 있다** — 그래서 정량 순위(`original_ranking`)를 항상 병기해 담당자가 판단하게 한다. 실제로 우리 실호출 테스트에서도 같은 입력에 대해 조정 없이 Score 1위를 유지한 응답이 나온 적이 있고, 그 경우에도 카드에는 원 순위와 사유가 그대로 남는다 |
| 카드의 도로 접근성 근거는 AI가 찾아낸 건가 | 아니다 — **파이프라인이 사전 계산해 병기한 지표**(`road_distance_km`·`road_minutes`)다. AI 입력에도 함께 넣지만, 그 신호를 사유에 쓸지는 호출마다 다르다. 직선거리 근접도의 한계를 우리가 먼저 드러내려고 넣은 필드이고, 순위 산식에는 반영하지 않는다 |
| 왜 사북·고한이 아니라 영월인가 | 2025-10~12 실측에서 영월군은 소비저조도 0.78·정규화 감소 0.91로 종합 1위(0.84), 삼척시는 2위(0.52)다. 후보는 한 지역 독점을 막아 영월 3곳·삼척 도계 2곳으로 구성했고, 직선 8.3~19.5km·도로 27.0~46.5km다 |
| 삼척시는 시 전체가 대상인가 | 아니다. 하이원포인트 지역가맹 대상지역은 "정선군·태백시·영월군·**삼척 도계읍**"이라 파이프라인도 도계읍만 수집한다(소진공 상가 480곳, 시 전역 4,260곳 중 3,780곳은 자격 대상이 아니라 제외). 화면 라벨 "삼척시"는 원본 CSV 컬럼명을 따른 것이고 의미는 도계읍이다 — 우리 가맹점 데이터의 삼척 129곳도 전부 도계읍 주소 |
| 후보가 거점에서 가장 가깝다는 건가 | 아니다. 근접도는 **직선거리** 기반이라 만항재(해발 1,330m)를 넘는 구간에서는 실제 접근성과 뒤집힌다. 그래서 후보마다 도로 접근성을 함께 싣는다 — 직선 1위(5.6km)가 **차로 50분대**인데 직선 3~4위(7.6~8.0km)는 **차로 30분대**다. 다만 이 값은 공개 라우팅 API(OSRM) 추정치라 비포장·임도 구간이 섞일 수 있어 **절대 수치가 아니라 후보 간 상대 비교**로만 쓴다(그래서 거리 대신 소요시간으로 말한다). 한계를 감추지 않고 병기하되 순위는 검증 전이라 직선 기준 그대로 둔다 |
| 협동조합·법인도 후보로 나오나 | 아니다. 상시모집 신청 자격이 "대상지역 내 주소지·사업장을 둔 **개인사업자**(법인 제외)"라, 상호에 법인격 표기가 있는 상가는 후보 풀에서 제외한다(재산출에서 19곳 제외). 상호명 기반 **추정**이라 완전하지 않다는 점은 코드 주석·보고서에 명시했고, 최종 자격은 신청·심사에서 확정된다 |
| 전환율 20.5%가 강원랜드가 말하는 지역 사용 비율인가 | 아니다. 우리 값은 지역 사용 **건수** ÷ 입장 **연인원**(교대 합산)이라 비율이 아니라 "연인원 1인당 0.21건"이다. 강원랜드·언론이 쓰는 지역 사용 비율은 **금액 기준**(2024년 콤프 발생액 1,242.33억 중 지역 354.8억 = 28.5%)이라 종류가 다른 지표다. 자릿수가 비슷해 오인되기 쉬워 `근사 지표` 배지 + 고정 설명 문구(`conversion.proxy_note`)를 화면에 함께 띄운다 |
| 국세청 위험 신호로 지역을 비교했나 | 아니다 — 4개 시군이 14.6~15.1%로 **최대 편차 0.5%p**라 유의미한 차이가 없다. 비교 근거로 쓰지 않고 배경 정보로만 쓰며, 화면에도 '위험' 라벨·경고색·순위 정렬을 붙이지 않는다 |
| VOC 데이터는 왜 안 쓰나 | 실컬럼 확인 결과 리조트 시설 민원 집계뿐, 지역·가맹점 정보 전무 → 배제하고 국세청 데이터로 대체 |
| 국세청 데이터를 써도 되나 | 진단 참고용만. 처방은 항상 하이원포인트 가맹점 확충으로 고정 — 주체 충돌 없음 |
| 전환율 수치를 믿을 수 있나 | 건수/인원 단위가 달라 근사 지표 — 화면·발표 모두 배지 상시 고지. 정밀화(매출 기반)는 로드맵 |
| 시뮬레이션 수치를 믿을 수 있나 | 인과 효과가 아니라 반사실 전망이다. 임의 ±30%를 제거하고 최근 3개월 월별 가맹점당 건수의 25~75 분위수를 범위로 쓰며, 모든 출력에 가정임을 명시한다 |
| 가중치는 왜 그렇게 정했나 | 민감도 분석 — 가중치 조합 N개에서 Top3 유지율 X% 슬라이드 |
| KPI는 어떻게 계산하나 | 채택률은 대기 카드를 제외한 결정 완료 카드 중 승인 비율, 실행 전환율은 승인 카드 중 추진중·완료 비율이다. 평균 의사결정 시간과 승인 카드 지역 균형도 시스템 상태값에서 계산한다 |
| 성과가 정책 덕분인지 어떻게 아나 | 유사 점수 미실행 지역과의 간이 대조군 비교 — 로드맵 방법론 |
| 페이백 재원은 어디서 나오나 | 시스템은 시나리오 비교·제안까지. 재원 확보·최종 페이백률은 담당자·예산 부서 결재 사항 |
| 이미 하이원포인트가 하는 것 아닌가 | 기존 제도는 "적립 포인트를 가맹점에서 사용". 이 카드는 **적립 단계가 아니라 사용 단계**에서, **지역 가맹점 결제분에 한정해** 리워드를 얹는 설계다. 기존 약관과의 중복 적용 여부는 리스크 항목으로 명시해 담당자 확인 대상으로 남긴다 |
| 페이백이면 콤프를 더 발행하는 것 아닌가 (사행성 조장) | 아니다 — **발행액을 늘리지 않는 설계**다. 하이원포인트는 게임 참여시간·베팅액에 비례해 적립되는 콤프인데, 이 정책은 적립률을 손대지 않고 **이미 적립된 포인트를 지역 가맹점에서 쓸 때만** 리워드를 얹는다. 게임 참여 유인은 그대로 두고 사용처만 지역으로 돌리는 것이라 콤프 발행액 증가와 무관하며, 카드·프롬프트 문구도 "추가 적립·추가 지급"이 아니라 "지역 결제분 한정 사용 리워드"로 통일했다. 부정거래(콤프 부정사용) 제재는 강원랜드 기존 체계를 그대로 따른다 |
| 실제로 포인트를 지급하나 | MVP는 정책 설계+시뮬레이션까지. 자동 지급·정산은 결제 시스템 연동이 필요한 로드맵 |
| 다른 공기업은 왜 못 만드나 | 하이원포인트 내부 거래 데이터 + 「석탄산업전환지역 개발 지원에 관한 특별법」(구 폐광지역개발 지원에 관한 특별법)상 상생 의무는 강원랜드 고유 |
| 운영 비용은 | Lambda+DynamoDB 서버리스 + Vercel — 사실상 $0/월, 실비용은 LLM뿐 (Billing 캡처) |
| 카드 상세 지도에 카카오/네이버를 쓰지 않은 이유 | 500m 반경 근거 화면은 MapLibre+오픈 타일로 재현성을 확보하고, 방문객 위젯에서는 보유한 Kakao Maps JS 키를 활용한다. 키 문제에는 fallback이 있다 |
