## ① 페이백 손익 표기 — "페이백 한 만큼 남는가"

**구현:** 인센티브 정책 카드의 시나리오 표 아래에 **`재원 부담 대비 효과 전망` 패널**
([`PaybackImpactPanel`](../../frontend/src/components/PaybackImpactPanel.tsx))을 신설했다.
페이백률(3·5·7%)마다 세 가지를 나란히 보여준다.

- **효과**: 예상 추가 지역 사용 건수/월 = 최근 3개월 평균 입장 연인원(교대 합산) × 개선폭(%p) ÷ 100
  — 범위 막대(하한 진하게·상한 옅게)와 값 병기
- **부담**: "지역 결제액 100원당 r원 리워드 지급" 구조 표기 + `budget_note` 정성 표기
- **효율**: 페이백 1%당 개선폭(%p) — 세 시나리오를 같은 자로 비교

시나리오 표의 라디오 선택과 실시간 연동돼, 담당자가 요율을 고르면 해당 카드가 강조된다.

**원화 ROI를 만들지 않은 이유:** 13 문서 §2-13이 "원천 데이터에 금액 필드가 없어 예산·ROI는
산출하지 않는다"를 심사 대응 원칙으로 못박고 있다. 금액을 지어내는 대신, 지역 전환율의 정의
(건수 ÷ 연인원)를 그대로 뒤집은 **건수 환산**만 썼다 — 새 가정을 추가하지 않는 유일한 방법이다.

**심사 규칙 준수:** 패널 자체에 `근사 지표` 배지(절대 규칙 2)와 "가정 기반 전망" 고정 문구
(절대 규칙 3)를 넣었다. 계산식(기간·연인원 수치)도 각주로 그대로 노출한다.

**리뷰 후 보강(`e397881`):** 효율 비율에 증감 컴포넌트(▲·스크린리더 "증가" 낭독)를 쓰던 오용 제거,
기간 라벨을 연-월 전체 표기로(해 넘김 창 `2025-11~01` 오독 방지), 3개월 데이터가 안 되면 패널 미표시.

## ② 지역별 소비 분석 부족 — 드릴다운 신설

**구현:** 지역 소비 분석 화면에서 지역 필터를 고르면 **`{지역} 상세 분석` 그룹**이 나타난다
([dashboard/page.tsx](../../frontend/src/app/dashboard/page.tsx)).

- **업종 구성 도넛**: 전 기간 누적 사용 건수를 표시 6분류로 롤업
- **월별 사용 추이 라인**: 해당 지역의 12개월 흐름
- **상위 업종 상세 표**: 원 업종 18종 그대로 누적·비중·최근 3개월·직전 대비 증감

**데이터 경로:** `usage_monthly.json`(월×업종×지역 원장, 파이프라인 정적 산출물)을
`lib/api.ts`에 정적 import로 노출했다. **BE 엔드포인트 없음** — 분기 배치 산출물이라 mock/실API
양 모드 데이터가 동일하기 때문이며, 이 결정은 05 문서 §6에 기록했다(계약 변경 절차 준수).
파생 계산은 [`lib/regionAnalysis.ts`](../../frontend/src/lib/regionAnalysis.ts) 순수 함수로 분리했고,
업종 롤업 표는 정본(`pipeline/category_map.py`)을 복제하며 그 사실을 주석으로 남겼다.

**검증:** 원장 지역별 합계가 대시보드 `region_share` 수치와 전 지역 일치함을 확인했다
(고한읍 94,363 / 사북읍 163,663 / 삼척시 27,355 등). 정선군(잔여분)·삼척시(도계읍 한정) 각주 병기.

**리뷰 후 보강(`e397881`):** 원장이 6개월 미만일 때 직전 3개월 창이 1~2개월로 쪼그라들어 증감률이
부풀려지던 문제를 비교 불가(null) 처리로 차단, 증감 창 라벨과 계산이 같은 정의를 쓰도록
`shiftWindowLabel()`로 단일화, "▲0%" 모순 표기 수정(소수 1자리), 지역 선택 시 "상단 지표는
전체 기준"임을 안내 문구로 명시.

## ③ 승인 → 방문객 위젯 실시간 반영 시각화

**구현:** 데이터 흐름(승인·완료 → `revalidatePath` → 위젯 `force-dynamic` 갱신)은 이미 있었으므로,
**"반영되는 순간이 눈에 보이는 연출"**을 추가했다.

- **`/widget?live=1` 라이브 미리보기**: 4초 간격 `router.refresh()` + 헤더에 갱신 표시 칩.
  필터를 눌러도 유지된다. 담당자 화면과 위젯을 두 창으로 나란히 두고 승인→완료를 진행하면
  위젯에 배지가 몇 초 안에 나타난다 — 데모 시연 동선.
- **배지 등장 애니메이션(`pop`)**: 새로 반영된 확충·페이백 배지만 튀어 오르게. `prefers-reduced-motion` 존중.
- **동선 연결**: 인센티브 승인 확정 블록과 트래킹의 완료 전환 지점에 위젯 바로가기 링크.

**정확성 원칙:** 페이백 배지는 승인이 아니라 **완료** 시점에 붙는다(BE·mock 공통 로직 확인).
승인 직후 "배지 확인" 링크를 주면 빈 위젯을 보게 되므로, 화면 문구를 실제 흐름
(승인 → 트래킹 완료 → 배지)대로 적었다.

**리뷰 후 보강(`e397881`):** pop 애니메이션을 라이브 미리보기 전용 옵트인으로 변경
(일반 필터 클릭 시 전체 배지가 점멸하던 문제), 숨은 탭에서는 폴링 중지(`visibilitychange`),
완료 배너의 "반영되었습니다" 단정을 "반영 여부를 확인해 보세요"로 완화
(확충은 타깃 읍×업종에 가맹점이 있어야, 인센티브는 요율 확정이 있어야 반영되므로).

## ④ 추진경과 작성 시 변화되는 지표

**구현:** 백엔드가 계산하는 `metric_changes`(경과 리포트)는 이미 화면에 있었으므로,
**기록 단위의 변화가 보이지 않던 구멍**을 메웠다.

- **카드 이력 타임라인**([`ProgressRecordTimeline`](../../frontend/src/components/ProgressRecordTimeline.tsx)):
  기록마다 관측 지표 5종(사용 건수·전환율·활성 가맹점·사용액·집중도) 각각에
  **직전 기록 대비 증감(▲/▼)** 병기. 첫 관측·동일값 구분. "소비 집중도는 감소가 개선" 각주 고정.
- **기록 입력 폼**([`ProgressRecordForm`](../../frontend/src/components/ProgressRecordForm.tsx)):
  저장 성공 시 "이 기록으로 갱신된 실제 관측 성과" 요약 칩 + 카드 이력·경과 리포트 바로가기.

**리뷰 후 보강(`e397881`):** 서버 페이지네이션(50건)으로 잘렸을 때 페이지의 가장 오래된 기록을
"첫 관측"으로 오표기하던 것을 "표시 범위 첫 값"으로 구분, 저장 확인 칩과 타임라인의 소수 자릿수
통일(전환율·집중도 2자리), 직전값 계산을 O(n²) 재정렬 방식에서 서버 정렬을 신뢰하는
단일 패스로 교체(동시각 기록에서 델타 부호가 뒤집힐 수 있던 이중 정렬 제거).

## ⑤ 실제 관측 성과 입력란 500 리턴 — 미해결 (BE)

**FE 측 조사 결과:** 폼의 payload 생성은 정상이다 — 빈 값 제거, 정수/범위 검증
(`ProgressRecordForm` 199-227행), `idempotency_key` 처리까지 확인했다. 백엔드 라우트
(`backend/app/routes/progress.py`)는 알려진 오류를 400/409로 매핑하므로, 500은
`progress_records.record_progress` 내부 또는 DynamoDB 저장 단계의 **매핑 안 된 예외**다.

**다음 행동:** `docker compose up`으로 재현해 터지는 입력 조합과 백엔드 로그를 확보 → 유탁에게 전달.
FE에서 할 일은 재현·전달까지이며 수정 자체는 BE 영역이다.

## ⑥ 방문객 위젯이 너무 간단

**구현:** "찾기 화면"에 머물던 위젯에 정보 밀도를 추가했다
([widget/page.tsx](../../frontend/src/app/widget/page.tsx)).

- **필터 칩에 가맹점 수 표기** — 반대편 활성 필터를 반영한 "그 칩을 눌렀을 때 볼 목록"의 실제 크기
- **시행 중 페이백 상단 배너** — 전 지역 공통 리워드를 목록 스크롤 전에 먼저 알림
- **"이번 분기 새로 확충된 업종" 섹션 분리** — 확충 완료 매칭 가맹점을 먼저 보여줌
- 카드 마크업을 `MerchantCard`로 추출해 두 섹션이 공유

**리뷰 후 보강(`e397881`) — 중요:**
- 칩 카운트용 `api.candidates()` 호출이 503이면 **방문객 위젯 전체가 죽던 하드 의존 제거**
  (`.catch` 가드 — 칩 숫자는 장식이므로 실패 시 숨김)
- 페이백 배너를 필터링된 추천 목록이 아니라 **카드 상태에서 복원** — 필터 결과가 0건이어도
  시행 중인 페이백은 보인다 (전 지역 공통 정책이므로)
- 카운트 계산을 전체 배열 14회 스캔에서 단일 패스 집계로 교체

## ⑦ 날짜·요일·날씨별 업종 분석 AI 추천 — FE 단독 불가

**사유:** 현재 데이터의 최소 단위가 **월**이다(`usage_monthly.json` = 월×업종×지역).
일별·요일별 분석은 원본 CSV에 일 단위 데이터가 있는지부터 확인이 필요하고(파이프라인 담당),
날씨는 외부 API 결합이 필요한 별도 과제다. 실데이터 없는 분석 화면은 심사에서 역효과가
날 수 있어 이번 스코프에서 제외했다.

**다음 행동:** 원본 데이터의 일 단위 존재 여부를 유탁에게 확인 → 있으면 파이프라인 산출 추가 후
②의 드릴다운 구조를 재사용해 확장 가능.
