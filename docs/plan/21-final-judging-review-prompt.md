# 상생 나침반 — 공모전 최종 심사 대비 검토

너는 이 프로젝트의 코드 리뷰어가 아니다. **「공공데이터 활용 바이브코딩 경진대회」의 심사위원이자,
남은 시간에 점수를 가장 많이 올릴 방법을 찾아내는 전략가**다.

최종 목표는 단 하나다.

> **`docs/reference/산출물평가표.pdf` 기준 실제 점수를, 남은 시간 안에 가장 크게 올리려면 무엇을 고쳐야 하는가.**

평가 순서를 절대 뒤집지 마라: **지역 문제 → 공공데이터 → 분석 → 문제 발견 → 의사결정 → Action →
지역상생 가치 → 이를 떠받치는 기술 → (필요한 경우) AI.** AI가 화려한지는 평가 축이 아니다.
반대로, AI가 단순하더라도 공공데이터가 실무자의 의사결정을 실제로 바꾼다면 높은 점수다.

|---|---|---|

## 1. 확정 사실 — 다시 조사하지 말고 전제로 쓸 것

재발견에 시간을 쓰지 마라. 아래는 이미 확인된 사실이다. **단, ★ 표시는 반드시 직접 재검증**한다.

### 1-1. 공식 평가표 (`docs/reference/산출물평가표.pdf`) — 최상위 기준

| # | 평가 항목 | 평가 내용 | 배점 |
|---|---|---|---|
| 1 | 창의성 | 아이디어의 독창성 | 20 |
| 2 | **데이터 활용성** | 공공데이터 활용도 | 20 |
| 3 | 완성도 | 기능 구현·안정성 | 20 |
| 4 | 활용 가치 | 실용성·파급효과 | 20 |
| 5 | **사회적 가치** | 사회 문제 해결에 기여하는 정도 | 20 |
| | **합계** | | **100** |

- 각 항목 **1점부터 20점까지의 정수**. 0점은 없다 → 항목당 최저 1점, 실질 변별 구간은 12~19점이다.
- 순위는 **심사위원 전원의 평균**. 한 명의 극단적 저평가가 크게 작용한다 → **최악의 심사위원 한 명을
  방어하는 것**이 평균을 올리는 가장 효율적인 수단이다.
- **동점 시 1순위 「데이터 활용성」 → 2순위 「사회적 가치」.** 두 항목은 사실상 가중치가 더 높다.
- 시상: 1위 강원랜드대표이사상 · 2~3위 우수상 · 4~5위 장려상 (총 5팀).
- 평가표 문구: **"심사위원은 각 산출물을 직접 체험한 뒤 항목별로 점수를 부여합니다."**

### 1-2. 심사 실황 모델 — 이 프로젝트에서 가장 중요한 전제

제출 요구사항 안내 PDF와 `docs/plan/12-submission-compliance.md` §5가 규정하는 심사 방식은
**"배포 URL을 전시 플랫폼에 등록 → 심사위원이 직접 접속해 확인 후 심사"** 다.

따라서 관객이 둘이고, **1번이 압도적으로 중요하다.**

1. **무안내 심사위원** — 발표자 해설 없이, 임의 시점에, 처음 보는 화면을, 아마도 몇 분만, 어쩌면
   휴대폰으로 본다. 설명해 줄 사람이 없다. **화면이 스스로 설명하지 못하면 그 항목 점수는 없다.**
2. **발표장 심사위원** (15분 발표) — 해설이 붙는다. 부차적이다.

일반적인 공모전 프롬프트에 있는 "발표 첫 30초", "3분 데모 시나리오" 류에 분량을 쓰지 마라.
**이 프로젝트에서 그 자리를 대신하는 것은 "배포 URL 첫 화면 30초"** 다.

### 1-3. 프로젝트 실체 (재조사 불필요)

- **한 문장**: 강원랜드 하이원포인트 사용 데이터로 폐광지역 4개 시군의 소비 쏠림을 진단하고,
  강원랜드 지역상생 담당자가 "이번 분기 어느 지역·업종에 가맹점을 확충할지"를 근거와 함께 결정·추적하도록
  지원하는 의사결정 플랫폼.
- **활용 공공데이터 6종**: 강원랜드 하이원포인트 사용현황(CSV) · 하이원포인트 가맹점 상세정보(API) ·
  일자별 카지노 입장객 현황(API) · 소상공인시장진흥공단 상가정보(API) · 국세청 사업자현황(CSV 2종) ·
  기상청 초단기실황(API, 방문객 위젯 전용 실시간 1건).
- **데이터 규모 ★**: `data/raw/highone_point_usage.csv` 5,832줄(헤더 포함), 국세청 2종 약 5.4만 줄,
  산출물 `merchants.json` 1,679건 · `candidates.json` 5건 · 읍 순위 6곳 중 2곳 선정 · `risk_signal` 4건.
- **핵심 산식**: 1단계 읍Score = 0.5×소비저조도 + 0.5×소비증감 / 2단계 후보Score = ⅓×업종공백도 +
  ⅓×관광동선근접도 − ⅓×기존가맹포화도 (반경 500m). 정본은 `pipeline/common.py` 상수 + `p6_scoring.py`.
- **핵심 수치 ★**: 지역 전환율 20.5%(근사 지표) · 소비 집중도 43(보통) · 업종 분산도 87 ·
  영월군 종합 0.84로 1위, 삼척시 0.52로 2위 · 민감도 95개 조합 중 Top3 순위 유지 16%, **읍 선정 자체는 60% 유지**.
- **구성**: FE 8라우트(`/` `/dashboard` `/cards/[id]` `/proposals/[id]` `/incentive` `/tracking`
  `/tracking/new` `/widget`) · BE 16엔드포인트 · 파이프라인 산출 JSON 8종.
- **레포는 이미 Public**이고 커밋 이력 시크릿 스캔은 155커밋 전수 통과했다(감사 §10).

### 1-4. 이미 끝난 일 — 중복 금지

## 2. 검토 절차

아래 순서대로 수행한다. 병렬로 나눌 수 있는 탐색은 서브에이전트로 돌려도 좋다.
**모든 주장에는 `파일:라인` 또는 실행 출력이라는 근거를 붙인다. 근거 없는 추정은 쓰지 마라.**

### 단계 A — 제출 게이트 (탈락 방지, 최우선)

점수 이전에 **전시·심사 자체가 불가능해지는 조건**부터 확인한다. 제출 요구사항 PDF §4 체크리스트 8항과
`docs/plan/12-submission-compliance.md` §6을 기준으로, 각 항목을 **통과/미통과/확인 불가**로 판정하라.

특히 다음 세 가지는 현재 미해결 가능성이 높다. 실제 상태를 확인하고, 미해결이면 **다른 모든 발견보다
위에 배치**한다.

1. **배포 URL이 존재하는가.** README:8이 플레이스홀더다. 심사가 배포 URL 접속으로 이뤄지는 이상,
   이것이 없으면 총점은 0에 수렴한다. Vercel(FE)·SAM(BE) 배포가 실제로 돌았는지, `.env`와
   `infra/deploy-backend.sh`의 가드 조건이 만족되는지 확인하라.
2. **배포 환경의 쓰기 동작이 열려 있는가.** 감사 H1의 핵심이다. `DEMO_READ_ONLY`와
   `MUTATION_API_TOKEN`이 Lambda와 Vercel 양쪽에 **같은 값으로** 들어가야 한다. 코드 수정은 끝났지만
   **Vercel 대시보드 환경변수 등록은 사람이 하는 수동 작업**이라 아직 안 됐을 수 있다.
   안 되어 있으면 심사위원이 승인 버튼을 눌렀을 때 실패한다 = 완성도 항목 직격.
3. **시드 상태가 데모 서사대로인가.** 공개 URL이라 심사위원이 승인·반려를 눌러 상태를 오염시킬 수 있다.
   `backend/seed_demo.py --reset` 운영 계획(카드 5장: AC-001~004, INC-001)이 실제로 준비돼 있는지,
   심사 기간 중 리셋 수단이 있는지 확인하라.

추가로 확인: 시크릿 창 접속, 모바일 렌더, Vercel Password Protection OFF, Lambda 콜드스타트 체감,
README의 배포 URL·스크린샷·현재형 문구, 제출 양식 문안(§3).

### 단계 B — 무안내 자립성 워크스루 (이 검토의 심장)

**가능하면 실제로 띄워서 본다.** `docker compose up -d` 후 `http://localhost:3100` (FE) ·
`http://localhost:8000` (BE). 띄울 수 없으면 코드에서 렌더 결과를 재구성하되, **그 사실을 보고서에 명시**한다.

너는 지금 **강원랜드도 하이원포인트도 모르는 심사위원**이다. 배포 URL을 처음 열었다. 아무도 설명해주지 않는다.

8개 라우트 각각에 대해 다음을 기록하라.

| 항목 | 질문 |
|---|---|
| 5초 | 이 화면이 무엇을 위한 화면인지 알겠는가 |
| 30초 | 어떤 지역 문제를 다루는지, 이 숫자를 왜 봐야 하는지 알겠는가 |
| 다음 행동 | "그래서 뭘 하라는 건가"에 화면이 답하는가. 다음 클릭이 자명한가 |
| 막히는 지점 | 용어·약어·맥락 부족으로 이해가 끊기는 곳 (예: "하이원포인트"가 뭔지, "읍 Score"가 뭔지) |
| 빈 화면 위험 | 데이터가 없거나 API가 죽었을 때 무엇이 보이는가 |

그리고 반드시 **YES/NO로 먼저 답하고 근거를 써라**:

- **"해설 없이 배포 URL만 본 심사위원이, 이 프로젝트가 공공데이터로 무엇을 발견했고 담당자가
  무엇을 하게 되는지 이해할 수 있는가?"**
- **"실제 강원랜드 지역상생 담당자가 월요일 아침에 이 화면을 열 이유가 있는가?"**

첫 화면(`/`)이 이 부담을 감당하지 못한다면, **그것이 이 검토의 P0**다. 무엇을 어떻게 바꿔야 하는지
(문구·배치·1줄 설명·온보딩 요소) 구체적 대안까지 제시하라.

### 단계 C — 평가표 5개 항목별 채점

각 항목마다 아래를 작성한다. **점수를 후하게 주지 마라. 다른 4팀이 상을 나눠 갖는 상대평가다.**

```
항목명 (배점 20)
├─ 예상 점수: XX / 20   ← 정수
├─ 근거: 심사위원이 실제로 보게 될 것 (파일·화면 근거 포함)
├─ 가점 요소: 이 항목에서 우리가 확실히 가져가는 것
├─ 감점 요소: 냉정한 심사위원이 깎을 지점
├─ 예상 코멘트: 종합 평가의견란에 적힐 법한 한 줄
└─ +1~+3점 올리는 법: 남은 시간에 실제로 가능한 수정만
```

항목별로 **이 프로젝트에 특화된 확인 지점**은 다음과 같다.

**① 창의성 (20) — 아이디어의 독창성**
- 차별점 후보: "진단→제안→**승인**→추적→방문객 노출"의 폐루프. 공급 측(가맹점 확충)과
  수요 측(페이백) 양면 설계. 정책 결과가 방문객 위젯에 되먹임되는 구조.
- 위험: 대시보드+지도+AI 추천은 공모전에서 흔한 조합이다. **무엇이 남들과 다른지가 첫 화면에서
  보이지 않으면 "잘 만든 평범한 대시보드"로 읽힌다.** 이 위험이 실재하는지 판정하라.
- 판정할 것: 폐루프가 화면에서 **실제로 한 바퀴 돌아가는 게 보이는가**, 아니면 문서에만 있는가.

**② 데이터 활용성 (20) — 동점 시 1순위 tiebreaker**
- 6종 각각에 대해 표를 만들어라: 출처 / 실제 컬럼 / 단위 / 서비스 내 사용 위치(파일:라인) /
  분석 목적 / **이 데이터를 빼면 무엇이 무너지는가**.
- 활용 깊이를 Level 1~5로 판정하라 (1 표시 / 2 가공 / 3 분석 / 4 의사결정 지원 / 5 실행 연결).
  **데이터별로 다르게 나올 것이다.** 특히 국세청 데이터는 설계상 "진단 참고용"으로 격리돼 있는데
  (절대 규칙 6), 심사위원 눈에 이것이 **"신중한 설계"로 보이는가 아니면 "쓰다 만 데이터"로 보이는가**를
  판정하라. 후자로 읽힐 위험이 있으면 화면 문구를 어떻게 바꿔야 하는지 제안하라.
- 기상청 데이터도 같은 질문을 받는다 — 방문객 위젯 한 줄에만 쓰인다. 필수인가 장식인가.
- **가장 강한 무기**: 여러 데이터를 **결합**해야만 나오는 결론이 있는가. 예를 들어 하이원포인트 사용
  데이터 단독으로는 "영월이 낮다"까지밖에 못 가고, 소진공 상가 데이터를 겹쳐야 "영월 특정 좌표
  반경 500m에 동일 업종 가맹점 0곳, 상가는 있음"이 나온다. **이 결합 지점이 화면에서 보이는지**
  확인하고, 안 보이면 그것이 최대 손실 지점이다.
- 심사위원 질문 대비: "왜 굳이 이 공공데이터인가", "단순 시각화와 뭐가 다른가",
  "이 데이터로 기존에 몰랐던 무엇을 알게 됐나". 현재 프로젝트가 **화면만으로** 답하는지 판정하라.

**③ 완성도 (20) — 기능 구현·안정성**
- 감사 결과를 여기에 접붙인다. 단, **심사위원이 마주칠 수 있는 것만** 골라라.
  dead code 584줄·CI 부재·FE 테스트 0개는 심사 점수에 영향이 없다. 반면 버튼을 눌렀는데 에러가
  뜨는 것, 콜드스타트 3초 공백, mock 모드의 단계 전이 규칙 누락(감사 M1)은 직격이다.
- **"버튼은 있는데 동작하지 않는 기능"을 전수 조사하라.** 감사가 지목한 것 외에 배포 환경에서
  새로 생기는 것이 있는지 본다.
- 빈 상태·에러 상태·로딩 상태를 8개 라우트에서 확인. `/proposals/[id]`·`/tracking/new`에는
  `loading.tsx`가 없다(감사 L7) — 콜드스타트와 겹치면 백지 화면으로 보인다.
- 모바일. 심사 체크리스트에 명시된 항목이고, 심사위원이 실제로 휴대폰으로 열 수 있다.

**④ 활용 가치 (20) — 실용성·파급효과**
- "실제 담당자가 쓸 수 있는가"를 `docs/plan/16-product-and-production-roadmap.md`와 대조해 판정하라.
- 이 프로젝트에는 **정직하게 그어둔 경계**가 있다(README "현재 운영 경계": 카드 승인은 가맹 확정이
  아니라 접촉·검토 시작). 이것이 실무자 눈에 **신뢰**로 보이는지, **미완성**으로 보이는지 판정하라.
- 파급효과: 다른 지역·다른 공기업으로 확장 가능한가. 폐광지역 4개 시군 밖으로 나갈 때 무엇이 깨지는가.
- KPI 화면(채택률·실행 전환율·균형지수)은 **시스템 자기 상태값**이다. 심사위원이 "그래서 지역이
  좋아졌다는 증거는?"이라고 물으면 답이 있는가.

**⑤ 사회적 가치 (20) — 동점 시 2순위 tiebreaker**
- 수혜자를 구체적으로 특정하라: 폐광지역 소상공인 / 주민 / 강원랜드 / 방문객 중 **누구에게 무엇이**
  돌아가는가. 추상적 "지역상생"이 아니라 **1,679개 가맹점·5개 후보·2개 읍**처럼 셀 수 있게.
- 「석탄산업전환지역 개발 지원에 관한 특별법」상 강원랜드의 상생 의무라는 **제도적 맥락**이
  화면·README에 드러나 있는가. 이건 사회적 가치 점수의 강력한 근거인데 현재 발표 Q&A에만 있다.
- **역풍 위험을 반드시 점검하라**: 카지노 콤프(하이원포인트)를 소재로 한 서비스다.
  사행성 조장으로 읽힐 여지가 있는가? `docs/plan/11` Q&A에 "적립률을 손대지 않고 이미 적립된
  포인트의 사용처만 지역으로 돌린다"는 방어가 있는데, **이 방어가 화면에도 있는가, 아니면 발표에만
  있는가.** 무안내 심사위원은 발표를 못 듣는다. 이것이 사회적 가치 항목의 최대 리스크다.

### 단계 D — 정직성 설계의 양날 검토 (이 프로젝트 고유)

이 프로젝트는 **불확실성을 숨기지 않는 것**을 설계 원칙으로 삼았다. 화면 곳곳에 다음이 붙어 있다.

- `근사 지표` 배지 (전환율 렌더 11곳 전부) + "분자=건수, 분모=입장 연인원이라 비율이 아님" 설명
- "가정 기반 전망이며 실제와 다를 수 있음" 고정 문구 (14곳)
- AI 폴백 시 "AI 아님" 3중 표기
- 추천 순위 안정도 16% + 해석 주의 캐비엇
- 직선거리의 한계 병기, 법인 제외가 상호명 기반 **추정**이라는 명시
- 국세청 데이터에 순위·경고색을 붙이지 않음

**이것은 기술적으로 옳고, 심사에서 양날이다.** 다음을 판정하라.

1. 심사위원이 이 표기들을 **"데이터를 제대로 이해한 팀"** 으로 읽을 확률과,
   **"자기 지표를 자기가 못 믿는 팀"** 으로 읽을 확률. 어느 쪽이 더 높은가.
2. 캐비엇의 **밀도와 배치**가 적절한가. 화면 하나에 경고 문구가 3개 이상 겹치는 곳이 있는가.
   있다면 어디를 줄이고 어디를 남겨야 하는가.
3. 특히 **"추천 순위 안정도 16%"** — 이 숫자는 "우리 추천은 84% 확률로 흔들린다"로 오독될 수 있다.
   실제로는 Top3 **순위**의 유지율이고, **지역 선정 자체는 95개 조합 중 60%가 영월·삼척을 유지**한다.
   현재 화면(`/dashboard`)이 이 층위 구분을 하고 있는가? 안 하고 있다면 **가장 저렴하게 점수를
   지키는 수정**이 무엇인지 제시하라.
4. 반대로, **자신 있게 말해도 되는데 과하게 물러선 곳**이 있는가. 근거가 탄탄한 주장까지
   캐비엇으로 덮으면 창의성·활용가치 점수를 스스로 깎는다.

절대 규칙 6개(`CLAUDE.md`)는 지켜야 한다 — **규칙을 어기라는 제안은 하지 마라.** 규칙을 지키면서
표현·배치·우선순위를 바꾸는 방법을 찾아라.

### 단계 E — 주장 ↔ 구현 대조

README·`docs/plan/11` 발표 구조·제출 문안이 주장하는 기능을 전부 뽑아 실제 구현과 대조하라.

| 주장 기능 | 화면 | API | 실데이터 | 계산 로직 | 배포에서 동작 | 판정 |
|---|---|---|---|---|---|---|

판정: ✅ 실제 구현 / 🟡 부분 / 🔴 미구현 / ⚠️ 고정 시드 / ⚠️ 하드코딩 / ❓ 검증 불가

특히 **"발표에서 실제 기능처럼 설명할 위험"** 을 찾아라. 이 프로젝트에는 의도적으로 고정한 것이 있다.

- AC-002 "영월군 소매점" 카드는 **재현성을 위해 LLM 호출 없이 고정한 JSON**이다. 실시간 생성은
  별도 버튼(`실시간 확충 제안 생성`)이다. `docs/plan/11` §1은 이 구분을 대본에 못박아 뒀다.
  → **이 구분이 화면에서도 심사위원에게 전달되는가?** 무안내 심사위원은 고정 카드를 열고
  "AI가 방금 만든 것"으로 오해할 수 있다. 오해가 발생할 수 있다면 그 자체가 정직성 리스크다.
- `usageMonthly`·`usageDaily`가 실 API 모드에서도 정적 import인 것은 **계약된 설계**다(감사 §8).
  이것을 결함으로 보고하지 마라.

### 단계 F — 잔여 이슈 점수 기준 재정렬

`docs/audit/AUDIT-20260808.md` §12의 P1(4건)·P2(6건)·P3(6건)을 **평가표 점수 영향 기준으로 다시
줄 세워라.** 감사의 우선순위와 달라지는 항목이 반드시 있을 것이고, 그 차이가 이 검토의 부가가치다.

각 항목에 대해: 관련 평가 항목 / 예상 점수 영향(±N점) / 수정 난이도(분 단위) / 심사위원이 실제로
마주칠 확률.

### 단계 G — 심사위원 4인 독립 채점

각자 독립적으로 5개 항목을 채점하게 하라. **서로 다른 점수가 나와야 정상이다.**

- **A. 공공데이터 전문가** — 데이터 적절성·활용 깊이·필수성. 컬럼 단위로 캐묻는다.
- **B. 지역상생 실무자** (강원랜드 또는 지자체) — 이걸 진짜 업무에 쓸 수 있나. 현장 현실성.
  폐광지역 사정을 안다. 삼척=도계읍 같은 디테일을 알아본다.
- **C. 서비스·사업 전문가** — 첫 화면 이해도, UX, 지속 가능성, 확장성.
- **D. 기술 심사위원** — 실제 구현인가, 안정성, 데이터 처리, 아키텍처.

각자: 가장 높게 볼 부분 / 가장 낮게 볼 부분 / 첫 질문 / **5개 항목 점수와 총점** / 수상권 판단.
그리고 **4명 평균 총점**을 계산하라. 평균이 실제 순위를 정하는 값이다.

### 단계 H — 예상 질문 (20개, 신규만)

`docs/plan/11` §3에 이미 30개 이상의 Q&A가 준비돼 있다. **거기 없는 질문만** 20개 만들어라.
중복은 가치가 없다. 각 질문에 질문 의도 / 위험도(상·중·하) / **현재 방어 수준(문서·화면·둘 다·없음)** /
권장 답변 1~2문장.

무안내 심사 방식이므로, **"질문할 기회조차 없이 심사위원이 혼자 오해할 지점"** 을 질문 형태로
5개 이상 포함하라.

### 단계 I — 탈락 / 수상 시나리오

- **탈락 사유 TOP 7** — 심사위원 회의에서 실제로 나올 법한 말로. 각각 발생 가능성 / 치명도 /
  현재 상태 / 해결 방법.
- **수상 근거** — "공공데이터를 단순 시각화한 게 아니라 실제 지역상생 의사결정으로 연결했다"는
  평가를 **현재 구현으로 받을 수 있는가.** YES/NO와 근거. NO라면 무엇이 부족한가.
