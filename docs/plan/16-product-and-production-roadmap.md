# 16. 제품 존재 이유와 실운영 전환 로드맵

> 검토 기준일: 2026-08-05  
> 성격: 저장소·로컬 UI를 바탕으로 한 휴리스틱 사용자 검토. 실제 강원랜드 담당자 인터뷰나 현장
> 사용성 테스트를 대신하지 않는다.

## 1. 한 문장 정의

상생 나침반은 지역상생 담당자가 **어디를 먼저 검토할지 결정하고, 그 결정의 근거와 실행 결과를 끝까지
추적하도록 돕는 의사결정 Work Item 시스템**이다.

AI 정책 추천 서비스만으로 정의하면 존재 이유가 약해진다. 추천은 이미 보고서나 회의에서도 만들 수
있다. 이 서비스가 존재해야 하는 이유는 다음 단절을 줄이는 데 있다.

`공공데이터 진단 → 후보 비교 → 내부 승인 → 후보 접촉·적격성 검토 → 실행 → 방문객 노출 → 성과 회고`

현재 조직의 판단이 여러 파일과 담당자 기억에 흩어져 있다면 이 연결 자체가 제품 가치다. 반대로 실제
업무가 이미 하나의 시스템에서 같은 수준으로 연결돼 있다면, 이 제품은 별도 서비스보다 그 시스템의
의사결정 모듈로 들어가는 편이 낫다.

## 2. 핵심 사용자와 해결할 과업

| 사용자 | 해야 할 일 | 현재 제공 가치 | 실운영에 더 필요한 것 |
|---|---|---|---|
| 지역상생 실무자 | 이번 분기 우선 검토 지역·업종 선정 | 2단계 Score, AI 조정, 원 순위 병기 | 담당 권역·예산·접촉 이력, 후보 적격성 체크 |
| 승인권자 | 근거·리스크를 보고 승인/보류/반려 | 카드 상세, 시뮬레이션, 상태 결정 | 전자결재 연동, 승인 의견, 권한·감사 로그 |
| 실행 담당자 | 사업자 접촉부터 계약 결과까지 추적 | 검토중/추진중/보류/완료 상태 | 담당자·기한·체크리스트·첨부·알림 |
| 방문객 | 실제 사용 가능한 가맹점 선택 | 지역·업종 필터, 길찾기, 정책 배지 | 현재 위치 선택 동의, 영업 여부·운영시간 최신화 |
| 성과 관리자 | 정책이 소비 분산에 기여했는지 회고 | 시스템 상태 KPI | 시행 전후 코호트, 비용, 실제 신규 이용, 대조군 |

첫 번째 주사용자는 방문객이 아니라 **지역상생 실무자와 승인권자**다. 방문객 위젯은 별도 목적의 추천
앱이 아니라, 내부 결정이 실제 수요 노출로 이어졌음을 보여주는 실행 채널이다.

## 3. 실제 사용자 여정 점검

### 3.1 담당자 여정

| 단계 | 사용자가 묻는 질문 | 현재 판단 | 반영 또는 후속 조치 |
|---|---|---|---|
| 홈 | 지금 무엇을 봐야 하나? | 카드와 헤드라인은 명확함 | 데이터 4개월 경과 시 전 화면 갱신 경고 표시 완료 |
| 후보 비교 | AI가 왜 순위를 바꿨나? | 원 Score와 설명을 함께 볼 수 있음. 기존에는 숫자와 AI 문장이 모순될 수 있었음 | 후보명·Score·순위·상태·도로시간 문장을 서버가 정본 데이터로 재생성하도록 수정 |
| 승인 | 이 사업자가 실제 후보인가? | 상권 후보와 가맹 가능한 사업자를 혼동할 위험 | `candidate_verification` 미확인 상태와 5개 점검 항목 표시 완료. 실제 검증 저장 기능은 P0 |
| 시뮬레이션 | 효과가 결정할 만큼 큰가? | 42.5→42.5와 0.0~0.1%p만 보면 계산 실패처럼 보였음 | 예상 월 이용건수·추정 근거·기준월·효과 판정·보류 안내 표시 완료 |
| 실행 | 같은 대상을 또 추진하고 있나? | 동일 대상의 활성 카드가 중복될 수 있었음 | 승인 대기/검토중/추진중/보류/완료 전 상태를 신규 후보에서 제외하도록 수정 |
| 회고 | 이 결정이 실제 성과를 냈나? | 카드 완료와 시스템 KPI까지만 확인 가능 | 실제 이용·비용과 연결한 시행 전후 성과 측정은 P1 |

### 3.2 방문객 여정

| 단계 | 사용자가 묻는 질문 | 현재 판단 | 반영 또는 후속 조치 |
|---|---|---|---|
| 탐색 | 내 주변인가? | 위치 권한 없이 리조트 거점 직선거리로 정렬하면서 “내 주변”으로 오해할 수 있었음 | 하이원리조트 거점 기준과 산악 도로 오차를 명시하도록 수정 |
| 선택 | 왜 이 가맹점이 먼저인가? | 완료된 확충 업종 우선 정책은 제품 루프와 잘 맞음 | 정책 우선·그 외 거점 거리 기준을 명시 |
| 방문 | 지금 실제로 영업하고 있나? | 정적 가맹점 데이터만으로 보장할 수 없음 | 영업 상태 최신화와 마지막 확인일은 P0 |
| 이용 | 혜택이 실제 적용되나? | 완료된 인센티브 카드만 배지에 반영하는 구조는 안전함 | 실제 약관·정산 시스템 연동 전에는 “운영 시나리오” 경계를 유지 |

## 4. 현재 제품성 평가

| 관점 | 평가 | 근거 |
|---|---|---|
| 문제의 중요도 | 높음 | 진단에서 실행까지 연결하는 업무는 반복되고, 누락·중복 시 비용이 생김 |
| 차별성 | 중상 | 대시보드가 아니라 승인 가능한 Action Card와 위젯 반영 루프를 가짐 |
| 설명 가능성 | 중상 | 원 순위·근거·출처가 있으나 운영 데이터 검증이 더 필요 |
| 담당자 사용성 | 중상 | 흐름은 짧고 상태가 명확함. 담당자·기한·의견 기능은 없음 |
| 방문객 사용성 | 중 | 필터·길찾기는 유용하나 현재 위치와 영업 최신성이 없음 |
| 실운영 준비도 | 낮음 | 인증·권한, 후보 적격성, 자동 데이터 갱신, 감사·성과 측정이 미완성 |

결론은 **데모 가치와 제품 가설은 충분하지만, 현재 상태로 정책 운영의 단일 시스템이 되기에는 이르다**.
실운영 전환의 핵심은 AI 기능 추가보다 데이터 신뢰·업무 책임·성과 피드백을 닫는 것이다.

## 5. 이번 개선에서 적용한 원칙

1. LLM은 후보 선택과 비정량 리스크 초안에만 관여한다. 숫자·순위·상태 문장은 서버가 재생성한다.
2. `AI 근거 재검증`과 `사업자 적격성 확인`을 서로 다른 상태로 보여준다.
3. 같은 지역×업종의 활성 Work Item은 한 번만 존재한다.
4. 효과가 작으면 크게 보이게 포장하지 않고, 예상 사용량과 보류 선택지를 보여준다.
5. 현재 위치를 쓰지 않는 추천은 “내 주변”이라고 부르지 않는다.
6. 오래된 데이터로 계산은 재현하되, 운영자가 최신 데이터라고 오인하지 않게 경고한다.

## 6. 우선순위 로드맵

### P0 — 제한된 내부 파일럿 전 필수

- 인증·역할: 조회자, 실무자, 승인권자, 운영 관리자 권한 분리.
- 후보 적격성: 각 체크 항목의 상태·확인자·확인일·증빙을 저장하고, 필수 항목 미완료 시 `완료` 차단.
- 업무 책임: 카드 담당자, 목표일, 승인 의견, 보류 사유, 다음 조치 기록.
- 데이터 운영: 월별 자동 수집, 스키마·건수·최신월 검증, 실패 알림, 마지막 성공 시각 표시.
- 가맹점 최신성: 영업 상태와 마지막 확인일. 폐업·휴업 의심 항목은 위젯에서 자동 제외 또는 경고.
- 중복 제약: 애플리케이션 필터 외에 저장소 수준의 대상 키/조건부 쓰기로 동시 요청 경합 방지.
- 보안·감사: 사용자별 변경 로그, 원본/변경 전후 값, 개인정보 최소화, 보존·파기 정책.
- 파일럿 인터뷰: 실무자 3명 이상에게 최근 실제 의사결정 1건을 그대로 재현하게 하고 막힌 지점 기록.

### P1 — 효과 검증 가능한 제품

- 실제 성과 연결: 카드별 시행일, 유치 비용, 신규 이용 건수·금액, 4/8/12주 결과.
- 비교 설계: 시행 전후만 보지 않고 유사 지역·업종 대조군과 계절 효과를 함께 비교.
- 시뮬레이션 보정: 예측값과 실제값의 오차를 축적하고 폴백 단계별 정확도 공개.
- 업무 알림: 목표일 임박, 장기 보류, 데이터 갱신 실패, 확인 만료 알림.
- 위젯 개선: 사용자 동의 시 현재 위치 기준, 도로 이동시간 API, 영업중 필터. 동의 없으면 거점 기준 유지.
- 검색·필터: 담당자, 상태, 기한 초과, 검증 미완료, 지역·업종별 Work Item 조회.

### P2 — 확장과 최적화

- 예산 제약과 담당 인력을 포함한 포트폴리오 우선순위.
- 지역별 정책 실험 설계와 자동 회고 보고서.
- 전자결재·CRM·가맹 심사·정산 시스템 연동.
- 가중치 버전 관리와 정책 변경 전후 재현.
- 외부 방문객 채널에 재사용 가능한 추천 API/SDK 제공.

## 7. 성공 지표와 중단 기준

### 핵심 지표

North Star는 AI 카드 생성 수가 아니라 **기한 내 근거와 후속 조치가 기록된 의사결정 비율**이다.

| 지표 | 정의 | 파일럿 목표 |
|---|---|---|
| 의사결정 준비 시간 | 데이터 탐색 시작부터 승인안 제출까지 | 기존 방식 대비 30% 이상 단축 |
| 중복 업무율 | 동일 지역×업종 활성 Work Item 중복 건수 / 활성 건수 | 0% |
| 근거 완전성 | 출처·기준월·Score·적격성·담당자·기한이 모두 있는 카드 비율 | 95% 이상 |
| 기한 내 후속 조치율 | 승인 후 목표일까지 다음 상태/사유가 기록된 비율 | 85% 이상 |
| 예측 오차 | 예상 월 이용건수 대비 4/8/12주 실제값 오차 | 폴백 단계별 별도 추적 |
| 위젯 유효 방문율 | 길찾기 시작 후 실제 포인트 이용으로 이어진 비율 | 기준선 확보 후 개선 |

### 중단 또는 재설계 조건

- 담당자가 카드 작성 시간을 줄이지 못하고 동일 내용을 다른 결재 문서에 다시 입력해야 한다.
- 후보 적격성 미확인 비율이 높아 추천 대부분이 실행 단계에서 탈락한다.
- 데이터 갱신 주기가 분기 의사결정보다 느려 우선순위가 반복해서 무효화된다.
- 시뮬레이션 오차가 크고 방향조차 안정적으로 맞히지 못한다.
- 방문객 위젯이 실제 이용 증가로 이어지지 않고 내부 데모 장치로만 남는다.

이 경우 기능을 더 붙이기보다 전자결재/CRM 통합, 후보 데이터 확보, 또는 내부 분석 모듈로의 축소를
우선 검토한다.

## 8. 검증 계획

1. 최근 완료된 실제 가맹 확충 사례 3건을 준비한다.
2. 담당자가 기존 방식과 상생 나침반으로 같은 사례를 각각 처리한다.
3. 준비 시간, 확인하지 못한 정보, 중복 입력, 승인 질문, 보류 이유를 기록한다.
4. 추천 후보 중 연락 가능한 비율과 적격성 통과 비율을 측정한다.
5. 승인된 카드만 4주 파일럿으로 운영하고 주별 실제 이용과 담당자 후속 조치를 수집한다.
6. 4주 후 위 성공 지표와 중단 기준으로 P1 투자 여부를 결정한다.

기능 시연 성공과 제품 성공은 분리해 판단한다. 사용자가 더 빨리, 더 안전하게 결정했고 그 결과를 다시
학습에 쓸 수 있을 때 비로소 서비스 존재 이유가 검증된다.
