> **사용법**: 아래 "프롬프트 본문" 전체를 슬라이드 생성 AI(Claude·Gamma·Copilot 등)에 붙여넣어
> 초안을 만들고, `[캡처]` 표시 자리에는 리허설 화면 캡처를 직접 삽입한다. 수치는 전부
> `data/processed/` 실산출(2025-12 기준월)이라 **임의로 바꾸면 안 된다** — 데이터가 갱신되면
> 이 문서의 수치부터 갱신할 것. 발표 구조는 11 문서 §2(15분), 표현 규칙은 CLAUDE.md 절대 규칙
> 6조를 그대로 따른다. 이 프롬프트로 못 만드는 것(라이브 데모)은 11 문서 §1 클릭 스크립트가 담당한다.

## 프롬프트 본문 (여기부터 복사)

당신은 공공기관 심사(경진대회)용 발표 자료를 만드는 전문 프레젠테이션 디자이너입니다.
아래 명세대로 **15분 발표용 슬라이드 18장**을 만들어 주세요. 명세에 없는 수치·주장·기능을
지어내지 말고, 모든 수치는 아래에 적힌 값을 글자 그대로 사용하세요.

### 프로젝트 개요 (전 슬라이드의 공통 맥락)

- 서비스명: **상생 나침반** — 강원랜드 지역상생 담당자의 분기별 의사결정 지원 AI 플랫폼
- 한 줄 정의: "예쁜 대시보드가 아니라, 담당자가 실행할 **의사결정 근거**를 만든다"
- 파이프라인: 진단(지역 소비 집중도·지역 전환율) → 2단계 스코어링 → AI 비교 설명 →
  **담당자 승인**(Action Card) → 추진 상태 트래킹 → 방문객 위젯 반영.
  공급 측(가맹점 확충 카드) + 수요 측(페이백 인센티브 카드)의 양면 설계
- 팀: 2인 (데이터·백엔드·AI·인프라 1인 + 프론트엔드 1인), 2박 3일, AI 코딩 도구 활용
- 기술: Next.js(Vercel) + FastAPI(AWS Lambda 서버리스) + DynamoDB + Python 파이프라인 + LLM(설명 생성 전용)

### 반드시 지킬 표현 규칙 (심사 대응 — 위반 시 감점 사유)

1. "Gini"·"HHI"·"지니계수"·"허핀달" 용어를 **어떤 슬라이드에도 쓰지 않는다**.
   항상 "지역 소비 집중도" / "업종별 소비 분산도"라고만 쓴다.
2. "지역 전환율"이 나오는 모든 슬라이드에 `근사 지표` 배지(또는 괄호 표기)를 붙이고,
   최소 1회는 이 설명을 그대로 싣는다: "분자=지역 사용 건수, 분모=입장 연인원(교대 합산)으로
   단위가 달라 비율이 아닌 근사 지표 — 강원랜드가 공개한 금액 기준 지역 사용 비율(2024년
   28.5%)과는 다른 지표". 두 수치를 나란히 비교하는 레이아웃은 금지.
3. 시뮬레이션·예상 효과 수치 옆에는 항상 "**가정 기반 전망이며 실제와 다를 수 있음**" 문구를 붙인다.
4. AI를 "실행한다·결정한다"고 쓰지 않는다 — "제안한다·의사결정 근거를 제공한다"로만 쓴다.
   확정 주체는 항상 "담당자 승인"이다.
5. AI 제안 화면·설명에는 **원래 정량 Score 순위가 항상 병기**된다는 사실을 명시한다.
6. 국세청 데이터는 "진단 참고용"으로만 언급한다. 처방(카드 대상)은 항상
   "하이원포인트 가맹점 확충"이다.
7. 가맹점을 "확보한다"고 쓰지 않는다 — "가맹 전환·우선 모집·유치"로 쓴다
   (가맹은 사업자가 신청하고 강원랜드가 심사하는 제도).
8. 페이백을 "추가 적립·추가 지급"으로 쓰지 않는다 — "**이미 적립된** 포인트의
   **지역 결제분 한정 사용 리워드**(콤프 발행액 증액 없음)"로만 쓴다.
9. 후보를 "거점에서 가장 가깝다"고 단정하지 않는다 — 직선거리와 도로 소요시간을 병기하고
   소요시간 중심으로 말한다.
10. 데모의 조정 사례 카드는 "**재현성을 위해 고정한 예시**"라고 슬라이드에 명시한다
    (실시간 생성은 별도 버튼 시연 — 호출마다 결과가 달라질 수 있음을 함께 적는다).
11. 국세청 위험 신호에 '위험' 라벨·경고색·지역 순위를 붙이지 않는다(중립 배경 정보).

### 디자인 지침

- 담당자 화면 톤 = **인디고** 계열(주색 `#4f46e5`, 다크 `#171139`, 연한 배경 `#eef2ff`),
  방문객 위젯 톤 = **그린** 계열(`#166534`, 배경 `#dcfce7`). 슬라이드도 이 두 톤을 역할
  구분에 그대로 쓴다(담당자 이야기는 인디고, 방문객 이야기는 그린).
- 고지 배지(근사 지표·가정 기반 전망)는 중립 슬레이트(`#475569` 글자 + `#f1f5f9` 배경) 칩으로 통일.
- 숫자는 크게, 문장은 짧게. 슬라이드당 핵심 메시지 1개. 표는 3~6행 이내.
- 한국어, 존댓말 헤드라인 금지(명사형 종결), 본문 14pt 이상 가독성.

### 슬라이드 구성 (18장 — 15분: 오프닝 1분 / 문제 2분 / 데모 9분 / 데이터·AI 2분 / 클로징 1분)

**S1. 타이틀 (오프닝)**
- 제목: 상생 나침반 — 강원랜드 지역상생 의사결정 지원 AI 플랫폼
- 부제: "우리는 예쁜 대시보드가 아니라, 담당자가 실행할 근거를 만들었습니다"
- 팀명·2인·2박 3일 표기. 배포 URL과 QR 코드 자리.

**S2. 문제 정의 ①**
- 헤드라인: "리조트는 붐비는데, 소비는 지역으로 얼마나 흘러갈까?"
- 내용: 폐광지역(정선·태백·영월·삼척 도계) 상생은 강원랜드의 법적 책무(석탄산업전환지역
  개발 지원에 관한 특별법)인데, 담당자에게는 **지역 소비 집중도를 진단할 지표 자체가 없다**.
- 보조: 2025년 하이원포인트 지역 사용 507,628건이 지역 6곳에 어떻게 퍼져 있는지 아무도
  한눈에 보지 못했다.

**S3. 문제 정의 ②**
- 헤드라인: "데이터는 흩어져 있고, 후속 조치는 끊긴다"
- 3열 비교: (좌) 공공데이터 CSV·API가 따로 논다 → (중) 후보 선정이 감(勘)에 의존 →
  (우) 승인 후 추진 경과를 아무도 추적하지 않는다.
- 하단 전환 문구: "진단 → 후보 비교 → 의사결정 → 실행 추적 → 방문객 노출까지 **하나의
  감사 가능한 Work Item**으로 잇는다."

**S4. 솔루션 개요 (아키텍처 1장)**
- 좌→우 플로우 다이어그램: 공공데이터 4종(하이원포인트 사용현황 CSV·카지노 입장객 API·
  하이원 가맹점 API·소진공 상가 API) → 파이프라인(진단 지표·2단계 스코어링) →
  FastAPI+DynamoDB(Action Card) → 담당자 허브(승인·트래킹) → 방문객 위젯.
- LLM 위치를 명확히: "LLM은 **설명 생성 전용** — 수치 계산·대상 선택에 관여하지 않음"을
  플로우 밖 별도 상자로.
- 참고 상자: 국세청 사업자현황(진단 참고용 배경 지표).

**S5. 데이터 실사**
- 헤드라인: "16개 데이터를 검토했고, 6개는 이유를 적고 제외했다"
- [캡처] 실제 CSV 컬럼 헤더 캡처(cp949 원본) + 코드의 COLMAP 대응표.
- 핵심 수치: 사용현황 5,831행·507,628건·2025년 12개월·업종 18종, 가맹점 지오코딩
  1,679/1,682곳(실패 3곳 기록), 소진공 상가 6개 지역(삼척은 **도계읍만** 480곳 — 시 전역
  4,260곳 중 가맹 자격 없는 3,780곳 제외).
- 한 줄: "'실제로 열어봤습니까'라는 질문에 캡처로 답한다."

**S6. 진단 — 이번 분기 지역 성적표**
- 큰 숫자 3개: 지역 전환율 **20.5%** `근사 지표` / 지역 소비 집중도 **43/100 (보통)** /
  업종별 소비 분산도 **87/100** (기준월 2025-12).
- 표현 규칙 2의 고정 설명 문구를 이 슬라이드에 그대로 싣는다(연인원 1인당 0.21건 해석 포함).
- 보조 수치: 지역 비중 — 사북읍 32%·태백시 26%가 절반 이상, 영월군 3.7%(18,675건)로 최저.
  전월(일평균) −1.8%.

**S7. 2단계 스코어링 ① — 어느 읍부터?**
- 1단계(읍 단위): 소비저조도 50% + 소비 감소율 50% (기준: 데이터 최신 월부터 최근 3개월 vs 전분기).
- 실측 순위표: **영월군 1위 0.84**(저조 0.78·감소 0.91) / 삼척시 2위 0.52 / 고한읍 0.50 /
  사북읍 0.17 / 정선군 0.07 / 태백시 0.00 → 선정 읍 = 영월군·삼척시(도계).
- 한 줄: "사북·고한이 아니라 영월인 이유가 数에 있다 — 가장 덜 쓰이고 가장 빠르게 줄고 있는 지역."

**S8. 2단계 스코어링 ② — 그 읍의 어느 지점·업종?**
- 2단계(좌표 단위): 반경 500m 업종공백도 ⅓ + 관광동선 근접도 ⅓ − 기존 가맹 포화도 ⅓.
- 후보 Top 5 표(실산출): 영월군 음식점 0.50 / 영월군 소매점 0.49 / 영월군 숙박업 0.48 /
  삼척시 편의점 0.45 / 삼척시 카페 0.42. 각 행에 "반경 500m 내 동일 업종 가맹점 0곳" 같은
  근거 필드 1개씩.
- 하단 캐비엇(표현 규칙 9): 근접도는 직선거리 기반 — 예: 후보 1위는 직선 9.4km인데 도로는
  28.4km·35분(산악 지형). 그래서 도로 소요시간을 병기하고 순위 산식에는 넣지 않았다.

**S9. AI의 역할 — "제안까지만, 그리고 전부 검증된다"**
- 좌: AI 입력 7종 표(후보 Score·추진 상태·계절성·최근 4분기 채택 이력·반려 이력·
  국세청 위험 신호(참고용)·타깃 요일 패턴(참고용)) + "서버가 확정한 제안 대상"이 별도 입력으로
  들어간다는 표시.
- 우: 3단 안전장치 — ① 제안 **대상은 서버가 결정론으로 확정**(같은 입력이면 항상 같은 후보),
  ② LLM은 비교 설명·비정량 리스크 문장만 작성, ③ 화면에 나가는 수치·순위·상태는 서버가
  정본 데이터로 재검증(`AI 생성 · 서버 검증됨` 칩, 실패 시 `규칙 기반 설명` 칩으로 정직 표기).
- 시스템 프롬프트 전문 인용 상자(07 문서 부록 A-1의 **현행본** — "대상을 바꾸거나 새 사실·수치를
  만들지 말고…"로 시작하는 버전만 사용, 구판 인용 금지).

**S10. 라이브 데모 안내 (9분의 시작)**
- 데모 동선 9단계를 아이콘 타임라인으로: 허브 헤드라인 → 고정 조정 사례 → 실시간 생성 버튼 →
  카드 상세(1·2단계 근거+지도) → 가맹 전환 시 예상 효과 → 승인 → 트래킹(적격성→완료) →
  방문객 위젯 반영 → 인센티브 카드.
- 구석에 백업 고지: "네트워크 장애 시 로컬 스택/녹화본으로 즉시 전환(3중 백업)".

**S11. 조정 사례 — 고정 예시와 실시간 생성을 나란히**
- 좌 [캡처] 고정 카드(영월군 소매점): 배지 "진행 중인 건 제외하고 선택" + **원 정량 순위 병기**
  화면. 상단에 라벨 "**재현성을 위해 고정한 예시**(LLM 호출 없는 시드)".
- 우 [캡처] "실시간 확충 제안 생성" 버튼 결과. 라벨 "실호출 — 결과는 호출마다 다를 수 있음".
- 메시지: 정량 1위(음식점)는 이미 승인·추진 중 → 서버가 중복 제안을 걸러 선택 가능한 1위
  (원 순위 2위, Score 0.49)를 제안. 원 순위가 항상 병기되므로 판단은 담당자가 한다.

**S12. 시뮬레이션 — 반사실 재계산**
- [캡처] "가맹 전환 시 예상 효과" 패널.
- 내용: 신규 가맹점 1곳 추가를 가정해 지역 소비 집중도를 재계산 — 예상 월 이용 건수는
  유사 가맹점의 최근 3개월 실적 분위수(25~75)로 범위 추정, 개선폭 약 0.1%p 수준.
- 정직 포인트: "효과가 '미미'로 나오면 미미하다고 말하고 **보류도 정상 선택지**라고 안내한다.
  방향이 불확실한 구간은 LLM을 아예 호출하지 않고 규칙 문구만 쓴다."
- 배지 필수(표현 규칙 3): 가정 기반 전망이며 실제와 다를 수 있음.

**S13. 트래킹 — 승인 후가 진짜 업무**
- [캡처] `/tracking` 리포트. 실측값: 기록 9건 · 완료율 50% · 목표일 내 완료 100% ·
  정체 1건(22일) · 미기록 1건.
- 메시지: 모든 수치는 **담당자가 입력한 관측값**에서만 집계(추정하지 않음 — 지역 사용액이
  비어 있는 것도 원천 데이터에 금액이 없어서 지어내지 않은 것). 적격성 5항목을 확인해야
  다음 단계로 넘어가는 순차 전이 — 상태 건너뛰기 불가, 전 이력 감사 기록.

**S14. 방문객 위젯 — 정책 성과가 방문객 화면으로**
- (그린 톤 전환) [캡처] 위젯: 완료된 확충 업종에 "이번 분기 확충 업종" 배지, 인센티브 완료 시
  페이백 배지.
- 오늘의 추천: 365일 실측 요일 패턴 기반(예: 영월군은 화요일 최대, 주말이 주중보다 15.2% 적음 —
  전 지역 기준선은 토요일 최대). 추천 문구는 실명 점포의 맛·분위기를 지어내지 않는
  **결정론 문구**(LLM 미사용).
- 메시지: 담당자의 승인·완료가 방문객 노출로 이어지는 **폐루프**.

**S15. 인센티브 카드 — 수요 측 설계**
- 페이백 3% / 5% / 7% 시나리오 표: 예상 전환율 개선폭(0.5~1.0 / 1.0~2.0 / 2.0~3.0%p,
  팀 설정 가정치) × 재원 부담(낮음/중간/높음).
- 필수 문구(표현 규칙 8): "**이미 적립된** 하이원포인트의 **지역 결제분 한정 사용 리워드** —
  콤프 발행액 증액 없음(사행성 조장 아님)". + 가정 기반 전망 배지.
- 페이백률 확정은 담당자 승인 시에만(3|5|7 중 선택) — AI는 시나리오 비교문만 작성.

**S16. 신뢰 장치 — 우리가 스스로 붙인 제약 (데이터·AI 설명 2분)**
- 6칸 그리드: ① 근사 지표 상시 고지 ② 가정 기반 전망 문구 고정 ③ AI는 제안만·승인으로만 확정
  ④ 원 정량 순위 상시 병기 ⑤ 국세청 데이터는 진단 참고용(4개 시군 편차 0.5%p라 비교 근거로
  쓰지 않음) ⑥ 화면·발표 용어 통일(내부 계산식 명칭 비노출).
- 가중치 민감도(정직 공개): 가중치 95개 조합 재계산 결과 Top3 유지율 **16%** —
  "가중치에 따라 후보가 달라질 수 있음을 **숨기지 않고 공개**하고, 그래서 기본 가중치는
  균등(1단계 0.5:0.5, 2단계 ⅓씩)으로 두고 원 순위 병기 + 담당자 판단을 설계의 중심에 놓았다.
  가중치 회귀 보정은 로드맵." (**주의: 이 수치로 '순위가 강건하다'는 주장을 만들지 말 것**)
- 테스트 71건 통과 · LLM 장애 시에도 규칙 기반 폴백으로 데모 완주(폴백 사실을 화면에 정직 표기).

**S17. 아키텍처·운영 비용**
- 스택 다이어그램: Vercel(FE) + API Gateway/Lambda/DynamoDB 온디맨드(BE) + 정적 산출
  JSON 서빙 + LLM API.
- 비용: 서버리스 프리티어로 **월 $1 미만**(실비용은 LLM 호출뿐) — [캡처] Billing.
- 재현성: 원본 CSV·API 캐시·산출 JSON 전부 레포에 커밋, 클린 체크아웃에서 산출 재현
  (지오코딩만 키 필요 — 커밋된 산출물이 재현성 담보).

**S18. 로드맵 + 클로징 (1분)**
- 로드맵 3개: 유사 점수 미실행 지역과의 대조군 성과 비교 / 매출(금액) 기반 전환율 정밀화 /
  페이백 자동 지급·정산 연동.
- 클로징 한 문장: "상생 나침반은 AI가 결정하는 시스템이 아니라, **담당자가 더 나은 결정을
  더 빨리 내리게 하는 시스템**입니다."

### 발표자 노트 (각 슬라이드에 포함)

각 슬라이드에 2~3문장의 발표자 노트를 함께 생성하되, S6·S8·S11·S16에는 아래 예상 질문
방어 요지를 노트에 포함하세요:
- "전환율 20.5%가 공식 지역 사용 비율인가?" → 아니다, 건수÷연인원 근사 지표. 금액 기준
  28.5%(2024)와 종류가 다른 지표라 병렬 비교하지 않는다.
- "500m 수요는 어떻게 계산했나?" → 500m는 수요가 아니라 업종공백도·포화도 계산 반경.
  수요는 읍 단위 1단계에서 분리 처리 — 단계 분리 설계.
- "AI가 틀리면 누가 책임지나?" → AI는 대상을 바꿀 수 없고 설명만 보조. 수치·순위는 서버가
  재구성하고 담당자 승인으로만 확정.
- "결국 설명만 하는 것 아닌가?" → 맞다. 수치 계산·대상 선택에 생성형 AI를 쓰지 않는 것이
  재현성과 감사 가능성에 맞는 설계다. AI의 값어치는 대안 비교와 리스크의 읽기 쉬운 정리다.
- "가중치는 왜 그렇게 정했나?" → 균등 가중 + 민감도 95조합 공개(Top3 유지 16%) + 원 순위
  병기로 담당자 판단 보존. 데이터 축적 후 회귀 보정이 로드맵.
